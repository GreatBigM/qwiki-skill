# AGENTS.md 章节结构（内嵌规范）

> 通用部分。qwiki import 时按此组织 AGENTS.md。
> 反模式仅保留通用条目，项目特定条目不入本文件。

## 标准章节结构

```
§1   项目概况 — 一览表（芯片/存储/内核/分区/manifest/Docker/编译入口）
§2   工程划分（编译产物维度）— 每项：路径/环境/构建/产出/协作边界/编译范围
§3   编译系统细节 — 构建脚本隐藏逻辑、工具链、defconfig、缓存
§4   <芯片> 固件分层架构 — 按项目实际芯片定义层数（可多份）
§5   OS/内核侧详情 — Boot→内核→BSP/SDK→中间件（对应于有 OS 的芯片）
§6   特殊设计机制 — 低功耗/双芯片协同等
§7   业务应用 + 交叉矩阵
§8   开发工作流 — 日常流程/快速命令/诊断表
§9   团队分工 — 角色表 + 协作原则
§10  关键文件索引
附录 A：未使用的 repo
```

## 架构深度分析顺序

```
① 系统架构设计        → system_design.md
② 各芯片架构          → <芯片>_design.md（每芯片一份）
③ Module 业务架构     → <项目>_module_<模块>_design.md（多份）
④ 特殊设计机制        → <机制>_design.md（低功耗/双芯片协作等，按需）
⑤ 低功耗实现          → 并入对应 <芯片>_design.md
⑥ 交互协议            → 并入 <机制>_design.md
```

## 常见反模式（通用条目）

- ❌ 描述协议/架构时用抽象分类（如"下行数据"）代替代码实际的数据通道枚举
- ❌ 修设计文档时只列外层封装文件，不列内层核心文件
- ❌ 系统设计文档堆叠子模块文件路径细节
- ❌ AI 猜 AGENTS.md 结构（应按 § 规范组织）
- ❌ 静态列目录代替编译验证范围
- ❌ 架构报告命名不一致
- ❌ 不同芯片平台混淆
- ❌ 审查时凭经验不读代码
- ❌ 直接修改现有文档而不先验证其中的事实声明
- ❌ 同一份 skill 内出现内容重复
- ❌ 在 skill 正文中混入当前工作区的实现细节
